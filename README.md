# V0.Programs.Gateways.Services0.Proxies.Routes

Полнофункциональный веб-интерфейс и прокси-клиент для взаимодействия со шлюзом маршрутизации нейросетей V0.Programs.Gateways.Services0.Routes.

Консоль предоставляет чат с поддержкой мультимодальности (вставка картинок и документов через Ctrl+V, Drag-and-Drop и проводник), динамический поиск и переключение моделей со шлюза, настройку параметров генерации, сохранение сессий диалогов и озвучку ответов через Fish Audio TTS.

**Совет:** Для лучшего опыта по распознаванию и анализу изображений (CV) используйте модели **Gemma 31B** и **26B**.

---

## Основные возможности

- Мультимодальный чат: отправка текста вместе с изображениями (PNG, JPEG, WebP, GIF) и документами (PDF, TXT, схемы). Автоматическая конвертация файлов в base64 с сохранением MIME-типа (V0FileAttachment).
- Быстрая вставка из буфера (Ctrl+V): скриншоты и скопированные изображения/файлы прикрепляются к сообщению прямо из буфера обмена.
- Drag-and-Drop: перетаскивание файлов в окно чата для мгновенного прикрепления.
- Выбор модели с живым поиском: загрузка списка доступных моделей напрямую со шлюза через /API/V0/Route/Models/Get, фильтрация по названию/провайдеру и группировка (Google, OpenRouter, Alibaba, Z.ai, LM Studio и др.).
- Персистентность сессий: история диалогов сохраняется на сервере в файле routes_sessions_data.json и дублируется в localStorage. Поддерживается создание, переименование и удаление диалогов.
- Синтез речи (TTS): кнопка «Озвучить» у сообщений ассистента, вызывающая эндпоинт /API/V0/Routes/Audios/TTS (Fish Audio) с автоматической ротацией токенов при лимитах.
- Параметры диалога: регулировка температуры креативности (v0Temperature) и задание системного промпта (systemInstruction).

## Системные требования

- Node.js: версия 18.0.0 или выше (рекомендуется LTS 20+)
- Пакетный менеджер: npm, pnpm или yarn
- .NET 8 SDK / Runtime: для запуска бекенд-шлюза V0.Programs.Gateways.Services0.Routes

## Быстрый запуск

### Шаг 1. Запуск бекенд-шлюза Routes
Убедитесь, что шлюз V0.Programs.Gateways.Services0.Routes запущен и слушает порт 8042 (значение по умолчанию в V0Config.json):

```bash
# Перейдите в папку шлюза
cd V0.Programs.Gateways.Services0.Routes

# Запустите проект
dotnet run
```

Шлюз запустится на http://0.0.0.0:8042.

---

### Шаг 2. Установка зависимостей прокси-сервиса
Перейдите в директорию прокси-клиента и установите зависимости:

```bash
cd V0.Programs.Gateways.Services0.Proxies.Routes

npm install
```

---

### Шаг 3. Запуск веб-интерфейса в режиме разработки

```bash
npm run dev
```

После старта в терминале появится ссылка на локальный сервер:
```text
  VITE v5.4.21  ready in 240 ms

  ➜  Local:   http://localhost:3005/
  ➜  Network: use --host to expose
```

Откройте http://localhost:3005 в браузере.

## Настройка портов и сетевых адресов

Все настройки портов находятся в одном файле — vite.config.ts:

```typescript
export default defineConfig({
  plugins: [react(), routesSessionStoragePlugin()],
  server: {
    // 1. Порт самого веб-интерфейса прокси
    port: 3005,

    proxy: {
      // 2. Адрес и порт бекенд-шлюза Routes
      '/API/V0': {
        target: 'http://localhost:8042',
        changeOrigin: true
      }
    }
  }
});
```

- Чтобы изменить порт интерфейса, поменяйте значение server.port (например, на 3010) или запустите команду с флагом:
  ```bash
  npm run dev -- --port 3010
  ```
- Если шлюз Routes запущен на другом порту или удаленном сервере (например, http://192.168.1.100:8042), измените поле target в блоке proxy['/API/V0'].

## Сборка для Production

Для сборки оптимизированного production-бандла выполните:

```bash
npm run build
```

Готовые статические файлы будут скомпилированы в директорию dist/.

Проверить собранный проект локально:
```bash
npm run preview
```

Примечание при развертывании в Production (Nginx / Caddy):
При деплое на постоянный веб-сервер настройте проксирование запросов с префиксом /API/V0/ на адрес шлюза http://127.0.0.1:8042/API/V0/.
